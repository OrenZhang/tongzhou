# 本地文件工作区

同舟托管的文档保存在用户数据目录内的 `.tzhou`。设置 `TONGZHOU_USER_DATA` 时，位置为该目录下的 `.tzhou`；用户选择的项目目录、指定的导出路径不移动。

```text
.tzhou/
  knowledge/
    documents/<文档 ID>.md
    history/<文档 ID>~<版本>.json
    directories/<目录 ID>.json
    libraries/<内容库 ID>.json
    files/<原件 ID>.<扩展名>
    index.md
    folders.json
  artifacts/
    <作品 ID>.<扩展名>
    records/<作品 ID>.json
  attachments/
    <附件 ID>
    records/<附件 ID>.json
  chat-workspaces/<会话 ID>/
  checkpoints/<SHA-256>
```

文档 Markdown 的开头是 `---` 包围的 JSON 元数据，后面是完整正文。标题、逻辑目录、来源和版本与正文在同一个文件中提交。目录文件保存名称、父目录和版本，使用稳定 ID，重命名目录不需要移动全部正文。每日记忆也使用这一文档格式。

保存先生成旧版本，再把新的完整文档写入同目录临时文件，刷新文件后原子替换。替换完成就是保存成功；导航生成失败不会把已保存的内容报告为失败。`index.md`、`folders.json` 仅供浏览，可以重建。搜索直接读取文件，不使用数据库中的文档副本或持久化全文索引。内容工具回执提供实际路径、正文长度和 SHA-256。

文件可以随 `.tzhou` 复制，正文外部修改会在下次读取时可见。编辑时必须保留完整元数据；客户端的版本检查和修订历史适用于通过客户端工具提交的变更，不应同时从外部编辑同一文档。

SQLite 保留会话消息、任务队列、运行状态、配置、授权关联等应用记录，不再保存知识正文、修订、目录、作品或附件记录。任务输入和来源摘录仍属于任务及会话历史，不是文档的另一份保存源。

1.0.0 直接使用当前文件格式，不执行旧目录搬迁、SQLite 文档转文件或历史镜像清理。SQLite 只接受当前 schema；不支持的格式明确报错，不自动修改为新格式。

加密备份包含 `.tzhou` 下的文档、版本、原件、作品、附件、会话工作文件及检查点；恢复与原有数据库恢复共用可恢复的目录切换日志。文件读取和备份拒绝符号链接越界。项目目录仍需用户自行备份。
