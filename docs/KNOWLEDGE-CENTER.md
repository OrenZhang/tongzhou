# 本地智库与每日记忆

模块名称统一为「智库」，界面分为「文档」与「知识与记忆」。内部 source/wiki/memory 类型、ID 和旧文件路径兼容保留，旧资料不需要复制或搬迁。整理文档 保存整理后的知识，资料来源保存上传原件和原文证据，每日记忆保留后台提炼的会话经验。检索仍以已收录内容和会话可访问范围为准。

文档区（笔记、原件与整理文档）支持最多 8 层目录：新建、重命名、移动、折叠和删除。目录按主题组织，独立于项目访问范围；父目录筛选包含子目录。页面可选择所属目录或移入“未分类”。删除目录及子目录会保留所有 整理文档 页并移到未分类；删除知识页仍需单独确认。目录信息保存在 SQLite 并同步为 `knowledge/folders.json`，整理文档 文件继续使用稳定 ID，移动不会破坏来源链接。目录管理方法统一注册到客户端管理工具；会话工具 `knowledge_folders` 可读取目录，`knowledge_write` 可选择 `folderId`。

## 目标与技术选择

把参考资料、会话发现和项目经验放进一个可检索、可维护、可引用的本地模块。资料是证据，不是指令或授权；知识模块不改变工具权限。

结构参考 [Karpathy 的 LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：原文、整理页、索引与维护流程分开。去重和来源版本参考 [LlamaIndex 的文档管理](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)。第一版复用 Electron、SQLite FTS5、现有 Markdown 渲染和 Agent 工具桥，不增加 Python 服务、向量数据库或额外模型账号。

[PageIndex](https://github.com/VectifyAI/PageIndex) 可用于后续长 PDF 的章节检索。本版仅保留可扩展的资料 ID、正文、目录与来源版本模型，没有安装或假称已经运行 PageIndex / LlamaIndex。

## 使用流程

侧栏「智库」维护资料。聊天输入区不再提供关联入口，智库不主动注入上下文；Agent 根据任务需要通过工具检索和读取，实际使用的内容保留在工具记录中。

1. 导入文本资料，或新建 Markdown 笔记，选择通用空间或项目空间。
2. 已完成轮次仅进入候选队列，记录现有消息的位置，不直接生成一条记忆。后台 Agent 在空闲后读取原文，筛掉问候和过程噪声，将值得保留的信息归并到当天唯一的记忆页。没有有效信息可跳过，不会为了每天一份而生成空页。
3. 「让 Agent 整理」使用当前会话的模型连接开启独立任务，读取资料、检索已有知识，保存关联来源的 整理文档 草稿。任务沿用客户端运行、停止、错误反馈和记录机制。
4. 后续会话的 Agent 可检索资料并补写草稿；新知识仅出现在当前聊天时，系统会保存最近消息摘录作为来源。不能通过专用知识写入工具覆盖人工内容或已确认知识。「核对并收录」提供明确的人工核对入口，记录版本与来源；每日记忆也可核对，后台新增条目再次进入待核对状态。
5. Agent 自行判断是否需要知识，先 knowledge_search 查找，再 knowledge_read 阅读原文。草稿与核对状态一并返回。旧版自动引用设置和普通会话绑定不再生效。
6. 「Agent 排查」创建独立只读任务，继承当前会话可访问的资料范围，分页盘点并读取原文，给出冲突、过时和缺口清单。结构检查是确定性检查，语义判断依赖模型，不宣称自动证明知识正确。

## 数据与检索

目录统一放在客户端数据目录的 `knowledge/`，页面「打开目录」定位实际路径：

```text
knowledge/
  index.md            # 自动维护的分类目录
  folders.json        # 整理文档 目录树的同步副本
  sources/<id>.md     # 原始文字资料 / 手写笔记
  wiki/<id>.md        # 整理后的知识页
  memories/YYYY-MM-DD/index.md # 当天唯一的分类记忆页
  revisions/         # 历史修订
  files/             # 原始上传文件
```

SQLite 保存规范化文档记录、引用、版本和全文索引，是客户端当前状态的依据；Markdown 是可读、可迁移的同步副本。请通过客户端编辑；直接修改副本不会自动写回数据库。整套资料和原件纳入现有加密备份与恢复。

- 文本文件按内容哈希去重；导入原文不可覆盖，笔记可编辑。
- FTS5 用于可分词的全文查询，中文短词使用有界关键词匹配；标题加权，页面最多返回 100 项。工具检索提供分页，排查工具能遍历当前范围。不是向量语义搜索。
- Markdown 标题生成文档目录；正文支持按偏移分段读取。
- 不做关键词预注入，不提供手动会话关联。只有模型发起检索或读取工具后，相应结果才进入本轮上下文。
- 模型根据聊天上下文形成查询词；读取工具记录资料 ID、版本和实际片段，检索摘要不能冒充已读全文。
- 项目会话可读取本项目与通用资料；普通会话记忆限定原会话。确认的通用 整理文档 可复用。用户明确发起的独立整理任务可读取选定来源，普通会话旧绑定不能扩大范围。
- 更新要求提交当前版本，避免并发覆盖。修订可恢复；恢复前版本仍保留。智库不设归档入口，旧版已归档内容恢复到列表，保留原来的核对状态、原件和修订历史。
- 来源更新、删除资料或会话、无来源 整理文档 和未提取正文均会提示复核。
- 资料、整理文档 和每日记忆支持直接永久删除，确认后清除正文、智库原件、修订历史和会话引用。原始上传位置的文件不受影响；关联 整理文档 保留并提示来源已删除。删除的会话记忆不会被自动补收，已有备份不受影响。

## Agent 接口

`knowledge_search`、`knowledge_read`、`knowledge_audit`、`knowledge_folders`、`knowledge_write` 随会话提供；只读 Agent 不获得写入工具。专用写入工具仅维护有来源的 整理文档 草稿。全部管理功能同时通过客户端能力注册表暴露，不另建一套适配目录；人工核对声明为手动能力，Agent 不能代替用户点击确认。

关闭后台记忆整理不影响用户明确要求的 整理文档 保存。会话指令会要求停止主动积累，仅在用户要求时调用写入工具。

## 后台记忆与轻量本体

- 按本地日期分组，同一天不同项目的条目汇入同一个文档；每条保留项目/会话范围。工具按条目过滤，不能因为共用每日文件而串项目。普通会话记忆默认限定原会话。
- 固定六类：偏好与约束、事实与背景、决策、经验与方法、待办与缺口、矛盾与变化。每条具有主体、关系、内容、发生时间、来源、范围和核对时间，是轻量的领域结构，不是图数据库或完整本体推理引擎。
- 客户端运行时每 30 秒检查一次队列；没有前台任务运行，且来源会话空闲至少两分钟后，每次按相同日期、范围和模型取最多四个候选轮次。只有一个后台整理任务，三分钟超时；HTTP 模型最多八轮工具交互。界面可立即整理一批或重试。
- 复用来源会话的模型连接，会消耗该模型额度；不另需模型账号。关闭客户端时不运行，未完成任务下次启动进入重试。失败指数退避，最多自动尝试三次；界面显示原因及最近整理结果，包括“无需新增”。
- 候选内容先遮蔽常见凭据。后台只获得 `memory_source` 和 `memory_commit`，不加载工作插件、项目文件工具或客户端管理能力。提交必须包含匹配原文的引文，模型无结构化提交视为失败；引文匹配不等于结论正确，所以生成内容保留待核对状态。
- 同日增量追加和去重，不覆盖人工已核对条目；矛盾保存为矛盾条目。完整版本历史可恢复。删除每日记忆后当天不会被后台重新生成。
- 旧版逐轮记忆迁移为标记“历史记忆待整理”的资料，保留原 ID、内容和来源链接，并加入候选队列。已归档旧记录先恢复，再按相同规则整理，避免无声删除历史。

## 当前边界与验证

文本格式可编辑或索引。单文件上限 25 MB，文本正文最多 200,000 字符；其他格式保留原件并标记待提取，尚未内置 PDF、Office、图片 OCR 或音视频转录。文档可分章节导入。

自动测试覆盖去重、全文查询、来源变化、修订与并发保护、项目隔离、模型主动检索、直接删除与旧归档迁移、自动收集、常见凭据遮蔽、只读限制和加密备份。桌面端到端测试实际通过工具桥完成读取与 整理文档 写入，并检查无预注入、工具结果引用和重启持久化；模型服务使用本地模拟响应，不代表真实第三方推理质量已经通过验证。

后续可在同一资料模型上增加解析器、PageIndex 章节检索、混合语义检索、跨日期主题归并和关系图展示。目前跨日期通过检索和 整理文档 复用，日期归档不等于已经实现全局语义记忆合并。

## 文档与知识投影（2026-10-05）

文档区借鉴 Obsidian 的目录、属性和双向链接组织方式。支持 [[文档标题]] 和 [[文档ID|显示名称]]；同名标题不猜测目标，提示使用 ID。链接不授予 Agent 额外访问范围。笔记和上传原件也支持目录；Markdown 仍是同步副本，不支持外部编辑自动同步。

知识与记忆区按实体浏览结构化事实，另有每日记忆视图。实体类型为项目、系统、人物、组织、概念、任务；关系包括依赖、属于、使用、负责人、部署于以及事实、偏好、决策等属性。实体 ID 由范围、类型、规范化名称确定，不同项目隔离；相同范围、主体、关系、值和有效期的事实合并证据，不覆盖原记录。当前不做语义别名归并，也不部署图数据库或完整推理引擎。

结构化 assertions 与文档一并保存、版本化和备份；没有第二份独立可编辑事实库。每项指定主体、类型、关系、目标、精确摘录和可选来源 ID、有效日期。实体关系需要目标类型，负责人限定人物或组织；文字属性禁止混入目标类型。摘录必须命中本文或关联来源原文，但命中不等于结论已被证明。来源变化、删除、上游证据失效会提示复核；启动命令、服务地址等单值属性在有效期重叠时提示可能冲突。时间截止后显示已过期，未提供日期不会推测。

Agent 的 knowledge_graph 每页最多 12 条，按当前会话权限过滤；knowledge_write 可附 assertions，始终保存草稿。用户点击「让 Agent 整理」后模型才提炼已有文档；历史文档不会在升级时被全量发送模型。每日记忆按条目投影到实体视图，跨日相同内容合并证据。新记忆保存原文引文；旧记忆未保存逐字引文时明确标注摘要。

用户可编辑文档中的结构化知识；每日记忆可逐条修正或移除，保留修订，移除条目的摘要指纹阻止当天原样补回。移除条目与永久删除整份资料不同，后者仍清除全部修订；语义改写不保证被指纹拦截。人工核对和记忆修正注册为手动操作。

所有检索都由工具按需发起，没有恢复自动注入或聊天关联。当前图谱是可重建的实体/关系列表，不是全局关系图画布；未集成 Obsidian 应用或外部知识服务。
