# 本地知识库与每日记忆

## 目标与技术选择

把参考资料、会话发现和项目经验放进一个可检索、可维护、可引用的本地模块。资料是证据，不是指令或授权；知识模块不改变工具权限。

结构参考 [Karpathy 的 LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：原文、整理页、索引与维护流程分开。去重和来源版本参考 [LlamaIndex 的文档管理](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)。第一版复用 Electron、SQLite FTS5、现有 Markdown 渲染和 Agent 工具桥，不增加 Python 服务、向量数据库或额外模型账号。

[PageIndex](https://github.com/VectifyAI/PageIndex) 可用于后续长 PDF 的章节检索。本版仅保留可扩展的资料 ID、正文、目录与来源版本模型，没有安装或假称已经运行 PageIndex / LlamaIndex。

## 使用流程

侧栏「知识库」维护资料；聊天输入区「知识」展示最近一轮的实际引用片段，并可进入知识库选取参考资料。

1. 导入文本资料，或新建 Markdown 笔记，选择通用空间或项目空间。
2. 已完成轮次仅进入候选队列，记录现有消息的位置，不直接生成一条记忆。后台 Agent 在空闲后读取原文，筛掉问候和过程噪声，将值得保留的信息归并到当天唯一的记忆页。没有有效信息可跳过，不会为了每天一份而生成空页。
3. 「让 Agent 整理」使用当前会话的模型连接开启独立任务，读取资料、检索已有知识，保存关联来源的 Wiki 草稿。任务沿用客户端运行、停止、错误反馈和记录机制。
4. 后续会话的 Agent 可检索资料并补写草稿；新知识仅出现在当前聊天时，系统会保存最近消息摘录作为来源。不能通过专用知识写入工具覆盖人工内容或已确认知识。「核对并收录」提供明确的人工核对入口，记录版本与来源；每日记忆也可核对，后台新增条目再次进入待核对状态。
5. 用户可显式引用资料，也可启用按需引用。自动引用仅选当前范围内、已收录、正文可用且来源版本未变化的资料；草稿只能手动引用。
6. 「Agent 排查」创建独立只读任务，继承当前会话可访问的资料范围，分页盘点并读取原文，给出冲突、过时和缺口清单。结构检查是确定性检查，语义判断依赖模型，不宣称自动证明知识正确。

## 数据与检索

目录统一放在客户端数据目录的 `knowledge/`，页面「打开目录」定位实际路径：

```text
knowledge/
  index.md            # 自动维护的分类目录
  sources/<id>.md     # 原始文字资料 / 手写笔记
  wiki/<id>.md        # 整理后的知识页
  memories/YYYY-MM-DD/index.md # 当天唯一的分类记忆页
  revisions/         # 历史修订
  files/             # 原始上传文件
```

SQLite 保存规范化文档记录、引用、版本和全文索引，是客户端当前状态的依据；Markdown 是可读、可迁移的同步副本。请通过客户端编辑；直接修改副本不会自动写回数据库。整套资料和原件纳入现有加密备份与恢复。

- 文本文件按内容哈希去重；导入原文不可覆盖，笔记可编辑。
- FTS5 用于可分词的全文查询，中文短词使用有界关键词匹配；标题加权，页面最多返回 100 项。工具检索提供分页，排查工具能遍历当前范围。不是向量语义搜索。
- Markdown 标题生成文档目录；正文支持按偏移分段读取。
- 自动上下文最多选 3 份资料；手动引用最多 20 份。引用总正文预算 12,000 字符，单份最多 3,000 字符；自动选择尽量取命中位置附近内容。完整正文仍可通过工具读取。
- “这个、之前、继续”等简短追问会结合最近两条用户消息检索。最近一轮引用记录区分手动引用、自动检索、工具读取，展示实际片段和版本；可排除后续注入，不会撤回已经发送的内容。明确要求时工具仍可读取。
- 项目会话可读取该项目、通用资料及显式引用；普通会话的未确认记忆不会自动流入其他普通会话。确认的通用 Wiki 可复用。
- 更新要求提交当前版本，避免并发覆盖。修订可恢复；恢复前版本仍保留。归档后退出检索及上下文，归档页可恢复。
- 来源更新、归档、删除会话、无来源 Wiki 和未提取正文均会提示复核。
- 归档资料支持永久删除，确认后清除正文、知识库原件、修订历史和会话引用。原始上传位置的文件不受影响；关联 Wiki 保留并提示来源已删除。删除的会话记忆不会被自动补收，已有备份不受影响。

## Agent 接口

`knowledge_search`、`knowledge_read`、`knowledge_audit`、`knowledge_write` 随会话提供；只读 Agent 不获得写入工具。专用写入工具仅维护有来源的 Wiki 草稿。全部管理功能同时通过客户端能力注册表暴露，不另建一套适配目录；人工核对声明为手动能力，Agent 不能代替用户点击确认。

关闭后台记忆整理不影响用户明确要求的 Wiki 保存。会话指令会要求停止主动积累，仅在用户要求时调用写入工具。

## 后台记忆与轻量本体

- 按本地日期分组，同一天不同项目的条目汇入同一个文档；每条保留项目/会话范围。工具和自动上下文按条目过滤，不能因为共用每日文件而串项目。普通会话记忆默认限定原会话；人工明确引用整份每日资料时可共享该页。
- 固定六类：偏好与约束、事实与背景、决策、经验与方法、待办与缺口、矛盾与变化。每条具有主体、关系、内容、发生时间、来源、范围和核对时间，是轻量的领域结构，不是图数据库或完整本体推理引擎。
- 客户端运行时每 30 秒检查一次队列；没有前台任务运行，且来源会话空闲至少两分钟后，每次按相同日期、范围和模型取最多四个候选轮次。只有一个后台整理任务，三分钟超时；HTTP 模型最多八轮工具交互。界面可立即整理一批或重试。
- 复用来源会话的模型连接，会消耗该模型额度；不另需模型账号。关闭客户端时不运行，未完成任务下次启动进入重试。失败指数退避，最多自动尝试三次；界面显示原因及最近整理结果，包括“无需新增”。
- 候选内容先遮蔽常见凭据。后台只获得 `memory_source` 和 `memory_commit`，不加载工作插件、项目文件工具或客户端管理能力。提交必须包含匹配原文的引文，模型无结构化提交视为失败；引文匹配不等于结论正确，所以生成内容保留待核对状态。
- 同日增量追加和去重，不覆盖人工已核对条目；矛盾保存为矛盾条目。完整版本历史可恢复。删除每日记忆后当天不会被后台重新生成。
- 旧版逐轮记忆迁移为标记“历史记忆待整理”的资料，保留原 ID、内容和来源链接，并加入候选队列。已归档旧记录保留，避免无声删除历史。

## 调研依据（2026-10-05）

| 系统                                                                                               | 借鉴点                                                          | 同舟的处理                                                   |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------ |
| [Codex 官方记忆说明](https://developers.openai.com/codex/memories/)                                | 跳过活跃会话，空闲后后台更新本地记忆，遮蔽敏感字段              | 候选队列与正式记忆分开，空闲调度、失败重试、与聊天任务隔离   |
| [Mem0 Add Memory](https://docs.mem0.ai/core-concepts/memory-operations/add)                        | 从交互中抽取事实/偏好，保留范围元数据；当前文档描述为追加式沉淀 | 结构化提炼、来源约束、明确作用范围；不把聊天全文直接视为记忆 |
| [Letta Memory & Dreaming](https://docs.letta.com/configuration/memory)                             | 后台整理近期对话与经验，避免打断前台工作                        | 独立后台整理任务，按天持续归并，界面展示队列状态             |
| [Graphiti 自定义本体](https://help.getzep.com/graphiti/core-concepts/custom-entity-and-edge-types) | 自定义实体、关系类型和字段，按类型组织领域知识                  | 主体、关系、分类、时间、来源与范围；暂不部署图数据库         |

这些是架构参考，没有集成或运行上述系统的服务端，也不声称复制其完整能力。当前重点是可观察、可核对、可恢复的本地流程。

## 当前边界与验证

文本格式可编辑或索引。单文件上限 25 MB，文本正文最多 200,000 字符；其他格式保留原件并标记待提取，尚未内置 PDF、Office、图片 OCR 或音视频转录。文档可分章节导入。

自动测试覆盖去重、全文查询、来源变化、修订与并发保护、项目隔离、显式引用、归档、自动收集、常见凭据遮蔽、只读限制和加密备份。桌面端到端测试实际通过工具桥完成读取与 Wiki 写入，并检查会话注入和重启持久化；模型服务使用本地模拟响应，不代表真实第三方推理质量已经通过验证。

后续可在同一资料模型上增加解析器、PageIndex 章节检索、混合语义检索、跨日期主题归并和关系图展示。目前跨日期通过检索和 Wiki 复用，日期归档不等于已经实现全局语义记忆合并。
