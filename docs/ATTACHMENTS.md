# 会话附件

输入框支持 Ctrl/⌘+V 粘贴图片，以及回形针按钮选择 PNG、JPEG、WebP 图片和 UTF-8 文本文件。可一次添加多个附件、发送纯图片消息；发送前可预览或移除。附件草稿按会话隔离，刷新和重启后保留，发送失败时仍可继续处理。

粘贴文字超过 4,000 个字符或 80 行时自动保存为 `.txt` 附件，保留原文。输入框仅显示紧凑卡片，可以继续填写任务要求。不会把截断后的文字冒充完整附件。

## 存储与发送

- 文件存入应用数据目录 `attachments/`，SQLite 只记录名称、类型、大小和标识；文件不会写入用户项目目录。消息和分支保留附件引用。
- 单文件最多 5 MB，每条消息最多 6 个附件、合计 12 MB；不支持的格式或超限输入会显示错误。
- 文本附件在模型请求中作为引用，模型使用只读 `read_attachment` 按字符分段读取全文。只能访问当前会话已发送的附件，无法读取任意路径或其他会话附件。
- 图片通过 OpenAI Chat / Responses、Anthropic、Gemini、Codex、ACP 的图像输入块传递，与电脑工具截图分开处理。最近图片可随模型切换交接；旧附件仍可通过工具重新读取。订阅引擎未声明图片能力时明确报错并保留附件，具体模型的视觉能力仍取决于服务端。
- Codex 的运行中补充同时传递附件；直接 API 与 ACP 在各自的补充边界消费附件。多 Agent 协作将本次附件交给每个参与者，保持原有只读权限。
- 文件内容属于用户提供的分析资料，不授予额外操作权限。HTML 等文本在预览中作为纯文本展示，不执行。

## 2026-10-04 验证

- Windows Electron 真实剪贴板图片粘贴、文件选择上传、纯图片发送、两张图像进入实际请求体、草稿刷新恢复、预览与移除。
- 长文本粘贴生成附件，首个请求只含文件引用；模型模拟端调用读取工具后收到完整末尾；重载历史后预览原文一致。
- 四类直连协议保留用户图像及最新电脑截图，Codex 跨模型交接和附件补充，ACP 图像能力支持/拒绝两种路径，协作附件分发与跨会话拒绝均有回归。
- 这些协议检查使用本地模拟服务，不等同于每个供应商的真实视觉模型均已验收；macOS 由 CI 覆盖，尚未实机验收。
