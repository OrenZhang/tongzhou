# 画布节点盘点与统一插件方案

日期：2026-10-19。盘点基线：`main` / `9ab02e3`。

状态：**首轮实现已落地，真实 ComfyUI 服务验收待完成**。本文记录当前实现、逐项处理决定、目标契约和验收条件；当前接口以 [节点插件 v1](./CANVAS_PLUGINS.md) 为准，实际使用与已知边界见 [ComfyUI 接入](./COMFYUI.md)。

## 1. 结论与范围

沿用现有画布、节点注册表、任务系统、服务连接和资源管理。整理节点的职责及配置，再给现有注册表增加 ComfyUI 适配。用户在同一画布中查看、编辑和连接本地节点与导入节点。

- 盘点基线为 **18 个内置节点**：8 个基础节点、5 个可视化节点、内容拆分、4 个工作流节点；本轮另增加 `comfyui.workflow` API 节点，导入的服务节点按工作流声明发现。
- 主处理决定：保留 11 个、合并 3 个、重构 4 个；没有证据支持立即删除某个完整业务能力。
- 文本、Markdown、便利贴归入同一文本来源插件的三个预设；图片、视频、音频保留各自入口，共用媒体执行与配置能力。
- ComfyUI 节点在画布中展开、可配置；内部生成图由 ComfyUI 整体执行。不是另开一个编辑器，也不只保存成一个无法查看内部的工具节点。
- 首轮合并文本执行、媒体参数别名与输入路由，增加展开导入和单节点 API 两个入口；保留旧 ID、media 配置容器和正常生成路径，不安装 ComfyUI 或改写历史。

### 合并后的入口

文本、Markdown、便利贴仍可以快速添加，但只是同一插件的不同预设；不是强行把用户喜欢的显示方式删掉。图片／视频／音频仍有各自的操作面板，但不建立三套执行器。白板是现有 `whiteboard` 文档模式，不计为第 19 个工作流节点，也不承担 ComfyUI 的执行。

## 4. 统一节点插件契约

扩展现有 `CanvasNodePluginDefinition` 和 `CanvasNodePlugin`，不引入新的插件平台、注册中心或任务调度器。先以可选字段兼容 v1；若最终改变了端口输出等不兼容语义，再明确升级契约版本，不能用 `apiVersion: 1` 偷换含义。

### 4.1 定义、实例和展示

- **定义**：插件 ID、插件版本、输入输出端口、配置 schema、默认值、执行方式、缓存策略及展示提示。
- **实例**：节点 ID、插件 ID、配置、资源绑定、布局和所用定义版本／指纹。`kind` 留作旧数据兼容与交互分类，不再决定业务执行分支。
- **预设**：定义 ID 加初始配置和展示选择，例如纯文本／Markdown／便利贴。它不是另一套 executor，也不是新的服务连接。
- **展示**：继续复用 `view` 和渲染器；预览可以不同，输入输出契约相同。
- **连接**：实例只存已有连接 ID。认证由服务连接管理，画布不维护另一份 token。
- **缺失定义**：节点和端口快照仍可显示、保存、导出；执行前明确标记缺失，不能用普通文本节点替换。

目标是把顶层 `media`、模型选择、保存目标的专有字段逐步归入对应插件配置。迁移不是一次性改名：需要同时覆盖 UI、执行、工具调用、导入导出和历史阅读，旧参数只能有一个权威读取来源。

### 4.2 端口、字段和值

沿用现有稳定 `fromPort`／`toPort`，补充类型命名空间、必填、单值／多值、以及可连线参数的声明。标量字段连接上游后使用连线值，不能同时保留一个含糊的本地覆盖值。

| 数据类别                                                    | 目标表达                                                        | 可跨执行引擎吗                                                         |
| ----------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 文本、数字、布尔、JSON                                      | 有类型的可序列化值                                              | 可以，须校验类型与大小；不把数字都转成字符串。                         |
| 图片、视频、音频、普通文件                                  | 沿用 `CanvasResource` 原件引用，外加可验证的媒体类型            | 可以，通过导出／上传／取回原件完成，不能只改类型标签。                 |
| ComfyUI `MODEL`、`CLIP`、`VAE`、`LATENT`、`CONDITIONING` 等 | 命名空间类型，例如 `comfyui:LATENT`；边记录内部节点及输出槽关系 | 只在同一个 ComfyUI 执行单元内部使用，不进 IPC、作品库或 Agent 提示词。 |

现有 `text/resources/ports` 输出继续由兼容层读取；新值通道先补类型和数量校验，再让通用路由读取，避免分类项、标量或结构化值在路由时丢失。泛型资源不能成为跨引擎连接任意内部类型的通行证。

可连接的图片端口继续表示资源；ComfyUI 运行时 `IMAGE` 是服务内数据，导出文件与它不是同一种表示，必须由输入／输出边界显式转换。

### 4.3 检查、执行与缓存

- 在现有插件接口增加可选的执行前检查钩子，报告连接、参数、资源、模型和权限问题；仍由 TaskService 在实际副作用前执行审批。
- 原生、Agent、媒体与 MCP 沿用节点执行；ComfyUI 插件声明“图执行”，由现有 `CanvasWorkflows` 先生成执行计划。
- 缓存默认采用保守规则。文本等确定性来源可复用；时间、外部写入、未知 MCP 工具及显式重新生成不能被通用缓存跳过。
- 模型、连接、工具 schema、定义版本、资源版本／哈希和种子策略纳入相关执行指纹。配置、连接或模型变化后重新检查。
- 外部任务的查询恢复、重试保存、重新提交是三个不同动作。断线或超时不代表远端任务失败，不能自动再提交一次。
- 输出保存与媒体目标位置复用同一组资源操作；生成节点仍可直接选择目标，不要求用户每次追加一个保存节点。

## 5. ComfyUI 接入决定

### 5.1 一套画布、一个注册表

从选定 ComfyUI 服务发现节点定义，将端口、参数和显示信息适配到现有节点定义；内置节点与导入节点使用同一个节点库和编辑器。不同服务可能装有同名但不同 schema 的节点：逻辑身份保留原始 `class_type`，解析出的定义身份还需含 schema 指纹，不能在全局注册表里相互覆盖。更换服务时重新匹配并报告差异。

ComfyUI 官方定义包含输入输出类型及控件元数据；适配器按目标服务实际返回的格式归一化，不假定所有 `/object_info` 都已经是最新定义格式。[节点定义规范](https://docs.comfy.org/specs/nodedef_json)

### 5.2 导入工作流与导入节点的含义

| 输入                          | 第一轮支持目标                       | 处理方式                                                                                      |
| ----------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------- |
| API 格式工作流                | 导入、编辑参数与连线、执行           | 识别 `class_type` 与具名 `inputs`；API 格式不含完整布局时生成布局，并明确这是自动布局。       |
| 普通 UI 工作流 JSON 0.4 / 1.0 | 导入布局与节点，检查后执行           | 保留原始 ID、位置、分组及未知字段；根据服务定义转换参数，不能仅凭 `widgets_values` 下标猜测。 |
| 目标服务已安装的自定义节点    | 发现、显示、配置；兼容检查通过后执行 | 使用通用表单；依赖前端 JS 才能完成转换或动态配置的节点标为待适配，不能声称全部兼容。          |
| 未安装节点、未知类型或缺模型  | 可查看、保存和导出，相关执行单元阻塞 | 显示缺失清单，保留原数据，不删节点和连线；服务恢复后重新检查。                                |
| Python 自定义节点代码包       | 不等同于工作流导入                   | 代码需要安装在 ComfyUI 环境；本客户端不因导入 JSON 就自动安装或执行它。                       |

官方普通工作流规范覆盖 0.4 与 1.0；官方 CLI 已提供 UI/API 工作流的转换入口，可研究其转换逻辑与测试样例，按许可复用，不另凭空设计一套对应规则。[工作流规范](https://docs.comfy.org/specs/workflow_json)、[官方 CLI JSON 接口](https://github.com/Comfy-Org/comfy-cli/blob/main/docs/json-output.md)

重路由、禁用／旁路、前端虚拟节点、动态端口、子图与列表／惰性求值都必须列入转换检查。不能解释的部分保留但阻塞执行；第一轮不宣称支持任意工作流。转换不把采样器误映射成我们的“图片生成”，也不自动合并或改写导入节点的语义。

### 5.3 展示是节点，调度是执行单元

ComfyUI 内部连线保持可见、可编辑，但不逐个调用我们的普通 `execute`。执行计划把具有相同连接且能一起编译的内部图组成一个单元，一次提交；现有原生节点仍是单节点单元。

1. 验证完整依赖图与边界端口，确定需要的输出节点。
2. 将同一 ComfyUI 单元编译成 API prompt，保留原始节点 ID 到画布 ID 的映射。
3. 在一个 TaskOperation 中上传边界素材、审批并提交，记录远端 `prompt_id`。
4. 将远端事件映射回画布节点的运行状态；没有收到的节点状态不能伪造成全部成功或精确耗时。
5. 只把已实际输出的文件取回为作品，交给后续 Agent／保存／通知节点。

分组取决于数据和执行边界，不取决于用户拖出的视觉分组。不能简单把所有同服务的节点合并：若中间依赖本地处理，需在可物化资源处切成两个单元，并检查合并后的依赖仍无环；内部模型／latent 边不能跨单元。暂时无法编译的混合图应指出具体连线，不能重复执行整张图来假装支持。

ComfyUI 自己有输出节点、变更检查和缓存语义；其内部依赖选择和缓存交给服务端，不在同舟再实现一遍 Python 节点调度。[自定义节点执行属性](https://docs.comfy.org/custom-nodes/backend/server_overview)

### 5.4 执行、停止和恢复

沿用 HTTP 提交、历史查询、文件上传／获取与 WebSocket 进度。远端单元身份、连接和工作流指纹记录在现有 `CanvasRun` 中；不新建一个并行任务库。WS 丢失后查询原任务；没有取得 `prompt_id` 的提交属于结果未知，需明确提示，不能自动重发。[服务接口](https://docs.comfy.org/development/comfyui-server/comms_routes)、[执行事件](https://docs.comfy.org/development/comfyui-server/comms_messages)

停止必须先区分排队、正在运行和仅本地停止跟踪。共享服务上的全局中断不能当成精确的单任务取消；只有能确认目标归属及接口能力时才请求远端中断。应用重启后可以恢复查询已有任务，但不承诺恢复 GPU 内存或从任意中间节点续算。

### 5.5 存储、导出与历史兼容

- 继续使用 `.tzhou/canvas/definitions`、`runs` 和现有 FileRecords，不另建数据库。
- 导入原件在 `.tzhou/canvas/imports/<id>.json` 保存一份不可变、带哈希的源记录；每个节点只保存源节点映射和配置差异，不复制整张原图。
- 在画布与节点定义中增加有大小限制的扩展元数据／端口快照。它们用于可移植身份、原件引用和兼容处理；服务凭据仍归连接管理。
- 项目包复用 CanvasTransfer 打包导入原件与必要素材；模板去掉连接绑定与本机路径，导入后重新绑定并校验。旧项目包继续可读，新增不兼容结构时明确升级包版本。
- 导出 ComfyUI JSON 从原件与当前图的差异重建；未改部分保留未知字段，已删除节点／连线不能被原件重新带回。未知语义必须报告；经过移植转换的字段不能声称逐字节无损。
- 原件或自定义参数可能含认证字段。可移植导出和会话读取需沿用并加强现有过滤，报告被移除字段；不能仅去掉连接 ID 就声称不含凭据。
- 当前上限为 200 节点、800 边、一次执行 50 个节点，节点配置 32000 字符。第一轮导入超过限制时保留原件并说明原因，不截断；图执行单元另设远端节点／负载上限，不能用“只算一个任务”绕过大小限制。
- 展示合并、旧 `media`／已有素材／Agent 图片节点的迁移采用读取归一化，用户保存新版本后落盘；不可原地改写历史运行快照或删除既有作品。

## 7. 验收清单

- **原有能力**：文本、Markdown、便利贴、资源原件、Agent、结构化拆分、图片／视频／音频、保存、定时、通知均有代表性回归；旧画布可打开执行。
- **参数一致**：同一服务在快捷面板、侧栏与执行前检查中得到相同结果；切服务后兼容参数保留、不兼容参数明确提示。
- **导入与编辑**：API、UI 0.4、UI 1.0；修改参数、重新连线、删除节点后导出再导入；ID、端口槽和未知字段不被悄悄改写。
- **依赖兼容**：缺节点／缺模型／不同服务同名节点／动态端口／旁路与重路由；能执行、可查看待适配、完全无法解析三种结果分开报告。
- **执行边界**：内部 latent 等类型不跨引擎；混合图无环；一个图单元只提交一次；所选输出和实际返回文件一致。
- **恢复与副作用**：断线、超时、重启后恢复查询；重复事件、部分结果、取消共享服务任务、再次保存都不造成重复生成或误停其他任务。
- **会话操作**：继续通过现有 canvas 工具发现、读取、修改和执行节点；只按需读取所选定义，不把整个 ComfyUI 节点目录放进模型提示词。
- **真实样例**：最小文生图、参考图、一个自定义节点流程，以及同舟文本 → ComfyUI → 保存的混合流程；视频在目标服务确有能力时另验收。

### 首轮实施说明

文本／Markdown／便利贴已共用文本来源执行；媒体参数别名由前后端共享，MCP 专用节点继续复用原调用器并采用保守缓存。图执行使用现有 TaskOperation；普通会话未配置 ComfyUI 时不加载专用工具。

为了保留正常流程，本轮没有机械搬迁所有顶层字段到 config，也没有删除旧 media.mode=existing 和无 media 的图片 Agent 路径。现有 configKey 已能统一配置入口；这些兼容路径集中保留，后续有实际迁移需求再移除，避免为了改名引入两份权威参数。

ComfyUI 导入、声明快照、命名空间端口、单值参数约束、单元执行、继续查询、原件打包和 API 节点已实现。原件在 CoSail 包内保留；ComfyUI 导出本轮只提供 API 格式，不承诺将 UI 专用字段重新编辑后无损导出。特殊前端控件／子图／旁路仍需适配，不能宣称任意工作流兼容。真实 ComfyUI 模型与 GPU 验证尚未完成。
