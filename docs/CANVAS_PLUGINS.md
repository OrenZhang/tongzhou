# 同舟画布节点插件 v1

节点插件统一使用 `CanvasNodePluginDefinition` 描述身份、版本、输入输出、配置与展示方式；通过 `CanvasNodePlugins` 注册，执行仍走现有工作流。画布保存插件 ID、配置、正文及资源引用，运行记录冻结插件版本。旧画布和旧插件继续兼容。

## 三种接入方式

| adapter  | 用途                                                | 执行与配置                                                   |
| -------- | --------------------------------------------------- | ------------------------------------------------------------ |
| `mcp`    | 调用已经连接的 MCP 服务；可封装搜索、生成等专用节点 | 通过现有工具目录生成参数表单，沿用认证、工具校验、审批与取消 |
| `visual` | Markdown、SVG、HTML、全景、便利贴等画布内容         | 注册前端 renderer，可输出文本或资源给下游                    |
| `native` | 随应用或 Cordis 扩展加载的自定义处理节点            | Zod 配置校验、宿主执行函数，可通过 context.task 使用任务系统 |

当前内置节点：`visual.markdown`、`visual.svg`、`visual.html`、`visual.panorama`、`visual.sticky-note`。在画布“添加节点”的下拉框选择；选中节点可编辑正文或配置。全景使用内容库/作品中的等距柱状图片，支持拖动和方向键环视，角度与视野可保存。3D 全景是图片球面浏览，不是通用 3D 模型编辑器。

图片、视频、音频生成同样通过节点注册表管理，属于调用媒体工具的内置节点插件。`content.split` 是使用会话模型的内容拆分插件。

## 内容拆分与端口连线

1. 添加“文本”节点粘贴小说，或添加“资源”节点选择内容库中的原文。
2. 添加“内容拆分”，把原文输出拖到它的“原文内容”输入端口。也可在配置面板的“连线”区选择端口连接。
3. 在“处理要求”输入总提示词，在“输出定义”中配置类别名称与各类提取要求；默认人物、场景、物品，最多 12 类。
4. 选中拆分节点运行。模型必须返回每类的 `name` / `description` 数组；缺失类别、非法 JSON、错误字段类型会明确失败，不把未经验证的结果传给下游。空数组表示没有提取到该类。
5. 从“人物”等分类端口连接图片节点的“提示词”，下游只收到对应类别。生成每个角色时，可先“展开人物为文本节点”，得到多个可编辑、可分别连接的文本节点；也可仅插入单项。

展开结果是所选运行的副本，重跑不会覆盖手工编辑。类别 ID 保持稳定，改名称不影响连线；在界面删除类别会同时删除对应输出边，可撤销。每类最多 100 项，结果总长最多 120000 字符；每张画布最多 200 个节点，展开超过上限时需逐项插入或另建画布。

| 节点                              | 输入端口                     | 输出端口                             |
| --------------------------------- | ---------------------------- | ------------------------------------ |
| 文本、Markdown、SVG、HTML、便利贴 | 无                           | 文本/源码                            |
| 资源、3D 全景                     | 无                           | 原始资源，附文字说明                 |
| 内容拆分                          | 原文内容                     | 自定义类别，每类为多个名称与文字描述 |
| Agent / MCP                       | 输入内容                     | 处理结果与资源                       |
| 图片生成                          | 提示词、参考图片             | 生成图片                             |
| 视频生成                          | 提示词、参考图片、首帧、尾帧 | 生成视频                             |
| 音频生成                          | 提示词                       | 生成音频                             |
| 保存到内容库                      | 待保存内容                   | 内容库资源                           |

节点两侧的端口可拖动连线；默认创建执行依赖，自动先运行上游。分类名与端口名在悬停或选中时显示。面板也可选择资料引用；引用不会触发上游生成，因此有计算任务的上游应使用执行依赖。

媒体参考图片端口会自动启用参考图模式，首帧/尾帧端口优先决定帧模式；这仍要求所选生成服务支持对应参数。首帧和尾帧分别只接受一张图片，顺序由端口决定。文字提示词不会混入参考图片的说明文本。直接连接“人物”类别是合并该类别的文字描述，不会自动对每项发起付费生成；需要分别生成时展开为文本节点连接各自的生成节点。

HTML/SVG 仅预览静态内容：先清洗，再放入无权限的 sandbox iframe，通过 CSP 禁止脚本与外部资源。Markdown 不执行 HTML，外部链接和图片不主动加载。插件渲染代码属于受信任的应用扩展，不能把用户正文当成代码执行。

## 共享声明

- `id`：全局唯一、小写字母开头，例如 `example.outline`。
- `apiVersion: 1`：SDK 契约版本；省略视为 v1。
- `version`：正整数，改变执行逻辑/配置兼容性时递增；旧运行拒绝换版本续跑。
- `kind`：沿用现有节点种类，扩展通常使用 `plugin`。
- `adapter`、`name`、`description`：接入类型与用户说明。
- `inputs` / `outputs`：兼容旧插件的输入输出能力描述。
- `ports: { inputs, outputs }`：每个端口声明稳定 `id`、显示 `label`、`types`（text/image/video/audio/resource）和可选说明。未声明时按节点种类生成默认端口。
- `dynamicOutputs: 'categories'`：输出端口从节点 `config.categories` 生成，用于内容拆分。
- `defaults`：新建节点时的正文、配置、宽高。
- `view`：renderer ID、正文标签、可选图片选择器。
- `configSchema`：由后端 Zod schema 转为 JSON Schema，前端复用通用配置表单。
- `source: true`：仅适用于无副作用的静态来源；允许不先执行节点就读取内容。静态引用不能启动任务，MCP 不允许声明此标志。

`node.pluginId` 是节点插件 ID；MCP 的 `node.config.pluginId` 是已授权服务连接 ID，两者不能混用。密钥保存在服务连接中，不能写进节点默认值。

连线新增可选 `fromPort` / `toPort`。指定端口时检查端口存在及类型兼容；泛型 resource 表示需要执行时解析的资源。旧的未指定端口连线仍传递完整结果。执行器可返回 `output.ports[id] = { text, resources, items? }` 供不同下游独立读取；`result` 是完整结果的保留端口。下游输入携带 `inputPort`，媒体插件据此区分提示词、参考图和首尾帧。复制、导入导出、保存及运行快照都会保留端口绑定。

## 原生处理插件

后端 SDK 入口：`electron/modules/canvas/plugin-sdk.ts`。

```ts
import { z } from 'zod';
import { defineCanvasPlugin } from './plugin-sdk';

const dispose = canvases.plugins.register(
  defineCanvasPlugin({
    definition: {
      id: 'example.outline',
      name: '整理大纲',
      kind: 'plugin',
      version: 1,
      inputs: ['text'],
      outputs: ['text'],
    },
    schema: z.object({ prefix: z.string().default('大纲').meta({ title: '前缀' }) }),
    execute: ({ node, inputs }) => ({
      text: String(node.config?.prefix) + '\n' + inputs.map((i) => i.text).join('\n'),
      resources: [],
    }),
  }),
);
// 将 dispose 交给所属 Cordis 扩展的清理流程。
```

`execute` 接收冻结的节点、运行、上游输入、权限与 AbortSignal。需要调用模型或工具时通过 `context.task` 使用宿主任务系统；不应绕开会话权限自己创建后台任务。

## MCP 专用节点

```ts
const dispose = canvasWorkflows.registerMcpNode({
  id: 'example.search',
  name: '网页搜索',
  version: 1,
  description: '使用已连接的搜索服务',
  tool: 'search',
});
```

用户仍需选择已启用的服务连接；若目录包含建议工具名则保留该选择。参数来自服务实际 inputSchema。没有显式填写时，宿主把节点正文与上游文本填入工具的 `prompt`、`text` 或 `query` 参数。普通“MCP 工具”节点支持直接选择已有服务和工具，无需开发专用封装。

## 自定义预览

前端入口：`src/features/canvas/node-renderers.tsx`，使用 `registerCanvasRenderer(id, Component)`，返回注销函数。组件接收 `api`、`node`、`output`、`patch`，只通过 `patch` 修改节点以保留撤销和保存流程。然后在后端定义 `view: { renderer: 'example.preview', textLabel: '正文' }`。缺少渲染器会显示明确提示，节点数据仍保留。

内置五种可视化节点是这套接口的实例；新增类型无需修改 CanvasBoard 的节点类型分支。

## 分发边界与验证

本版提供开发接入 API 和内置节点，不包含任意 URL JavaScript 下载执行器。infinite-canvas 的 React 插件依赖其宿主接口，不能直接运行；迁移时须适配同舟 renderer 和执行契约。后续远程安装可在此契约之上增加包清单、兼容版本与隔离运行机制。

画布 JSON/模板保留节点插件 ID 与可移植配置；项目包携带全景引用素材。MCP 服务连接不随包导出，导入后重新选择。插件缺失时保存的数据仍可查看、导出，但执行会明确报错。

验证：画布单测覆盖静态来源传递、全景图片、配置拒绝、MCP 注册与注销、版本冻结、结构化拆分、类别隔离、端口兼容与首尾帧映射；`npm run test:canvas` 覆盖五种预览、HTML 隔离、全景交互、端口拖线、模拟模型拆分、结果展开和保存重开。默认测试使用本地模拟服务，不调用付费生成接口。

# 工作流节点与自动化

内置节点均提供输入/输出端口，可组合为：定时触发 → Agent（搜索/读取/总结）→ 文本模板 → 保存到内容库 / 渠道通知。图片、视频、音频生成、内容拆分、MCP 工具、资源引用及可视化节点沿用同一插件接口。

| 插件 ID             | 输入                    | 输出                          | 配置                                                                                                    |
| ------------------- | ----------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| `workflow.schedule` | 无                      | `result`：触发说明与 UTC 时间 | 单次、每隔至少 5 分钟、每日、每周；时区；错过后补一次或跳过                                             |
| `workflow.template` | `context`：多个文本输入 | `result`：模板正文            | 正文支持 `{{input}}` 合并、`{{input.1}}` 按连线顺序取值，以及 UTC 的 `{{date}}`、`{{time}}`；不执行脚本 |
| `workflow.delay`    | `context`：正文/资源    | `result`：合并后的正文/资源   | 1–300 秒，可取消                                                                                        |
| `workflow.notify`   | `context`：消息正文     | `result`：发送回执            | 选择已启用通知目标；正文支持模板变量；1–4000 字，不截断、不发送附件                                     |

定时节点不会因添加、保存或导入而自动启用。选择普通执行会话、连接下游节点后，点击“保存并启用定时流程”。同一画布的同一定时节点只发布一条规则。规则固定画布版本和默认模型配置；画布保存为新版本后须重新发布，旧规则在下次触发时暂停并说明原因。定时运行只选取触发节点的依赖下游，并补齐执行所需上游依赖；无关分支不运行，单次最多 50 个节点。

调度复用自动化中心的队列、错过处理、避免重叠、取消、超时及执行记录。应用需保持运行、电脑需唤醒，不会自动修改电源设置。每次执行创建独立的自动化会话，权限为“需确认”，工具操作可能等待审批；超时默认 30 分钟。暂停规则停止后续调度及排队工作；已运行的流程需在自动化中心取消。异常退出不盲目重放，保留结果供检查后重试。

通知沿用渠道认证与发送日志，经 TaskService 的工具审批边界执行。目标固定在节点配置中，模型正文不能替换收件人。通知、等待及时间相关节点声明 `cache: 'never'`，不能被工作流缓存跳过。定时任务重试使用“任务 ID + 节点 ID”投递键，避免重复发送；失败或未知投递需查看渠道记录，同一任务重试不会自动再次发送，明确需要重新投递时启动新任务。取消会中止未完成的发送请求，但已送达的消息无法撤回。模板/项目导出移除通知目标，导入后必须重新选择，且不会启用定时任务。

后续扩展可添加条件分支、逐项遍历、失败分支和 Webhook 触发。目前执行器按依赖顺序运行，不把普通文本节点伪装成具有跳过/循环语义的控制节点；这些能力需要先扩展运行状态与执行预算。
