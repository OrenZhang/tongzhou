CoSail 是一个开源的 AI 桌面工作台，面向需要与 AI 一起完成项目的开发者和创作者。它把模型、项目文件、任务会话、知识库与创作工具放在同一个应用里：AI 可以读取上下文、调用工具、修改文件、执行检查，并将结果保存到你能继续使用的地方。

你可以围绕一个实际目标持续工作：**理解项目 → 修改代码 → 运行验证 → 保存交付说明 → 带着任务记忆继续下一轮**。

## 核心能力

### 编码与任务处理

- **在真实项目中工作**：读取和搜索文件，遵循项目指引，修改代码，执行终端命令，查看 Git 变更。
- **把验证纳入任务**：登记测试或构建命令作为完成检查；检查失败时，将结果交回同一任务线程继续修正。重试有次数限制，检查结果可以回看。
- **持续推进任务**：追问补充、排队执行、停止任务、恢复会话，用任务记忆记录进度、决定和待办，减少重复交接。
- **选择合适的模型**：接入 ChatGPT、Kimi、MiniMax 账号，或配置 Chat Completions、Responses、Anthropic、Gemini 协议的 API；本地模型可通过兼容 API 接入。支持按任务场景配置模型路由，实际能力取决于连接和模型。

### 让 AI 直接使用工作台

应用里的模块也可以成为 AI 的工具。你可以要求 AI 检索智库、整理资料、保存交付说明到内容库、读取保存结果，或操作工作流画布与白板。

AI 保存的文档和修改的画布会留在对应模块中，你可以打开检查、继续编辑和复用。插件开关、会话权限和操作确认仍然生效；需要登录或人工处理的步骤会交回给你。

### 可视化工作流与媒体创作

- **用对话搭建画布**：连接文本、资源、Agent、图片、视频、音频和工具节点，运行选区或整张工作流。
- **编排复杂流程**：支持条件分支、循环遍历、独立节点并行执行、失败分支和结果汇合。循环项按顺序处理，每项内部的独立节点可以并行；可查看逐项结果和错误，并按节点缓存策略复用仍有效的成功结果。
- **配置媒体节点**：根据节点插件能力设置提示词、参考图片、首尾帧、比例、清晰度和保存位置；生成结果可预览，并保存到作品、内容库或本地目录。
- **复用现有工作流**：连接自己的 ComfyUI 服务，导入工作流，保存模板，或导出包含资源的画布项目。
- **与 AI 一起画图**：内置 Excalidraw 白板，手动画草图和流程图，也可以让 AI 创建图形、修改选区与调整布局。

媒体生成需要配置相应服务或插件，支持的参数、输出类型和额度由服务决定。详见 [画布节点](docs/CANVAS_NODES.md)、[节点插件](docs/CANVAS_PLUGINS.md) 与 [ComfyUI](docs/COMFYUI.md)。

### 知识、记忆与工具扩展

| 能力               | 用途                                                             |
| ------------------ | ---------------------------------------------------------------- |
| 智库与内容库       | 收集资料、保存原文和来源、管理标签与版本，检索并复用任务成果。   |
| 任务记忆与每日记忆 | 保留任务交接信息；后台整理可复用的会话知识，并在智库中审阅。     |
| MCP 与 Skills      | 连接外部工具，安装或配置任务技能，把已有工作方式带进会话。       |
| 渠道与定时任务     | 从已配置的消息渠道接收任务，按规则调度工作；需要客户端持续运行。 |
| 本地权限           | 按会话选择只读、按需确认或完全访问，并管理插件和系统权限。       |

## 可以从这些任务开始

**修复代码并交付**

> 检查这个项目的导出功能，保留我已有的修改。先复现问题，再修复并运行相关测试。把变更说明和验证结果保存到内容库，留下下一轮需要注意的任务记忆。

**把资料变成可复用的成果**

> 阅读这组接口资料，结合项目现状整理接入指南。注明来源和仍需确认的问题，保存到智库；后续写代码时继续引用它。

**搭建批量创作流程**

> 建一张画布，逐条处理这些素材，按条件选择处理方式，让相互独立的步骤并行运行。失败时记录原因，最后汇总并保存结果。先搭好流程让我检查。

任务能否完成取决于模型、工具、运行环境与授权范围。测试和完成检查能提供执行证据，仍需按实际需求审阅最终成果。

## 下载与安装

从 [最新版本](https://github.com/OrenZhang/tongzhou/releases/latest) 页面选择与你的系统和处理器匹配的安装包：

| 系统                  | 架构  | 安装包                |
| --------------------- | ----- | --------------------- |
| Windows               | x64   | `.exe` 安装程序       |
| macOS · Apple Silicon | ARM64 | `.dmg` 或 `.zip`      |
| macOS · Intel         | x64   | `.dmg` 或 `.zip`      |
| Linux                 | x64   | `.AppImage` 或 `.deb` |

- 安装前可使用发布页的 `SHA256SUMS-*` 校验文件；签名状态与安装说明以对应版本说明为准。
- Linux 的电脑操作功能需要 X11 / XWayland；原生 Wayland 暂不支持。不同平台的系统集成功能存在差异。
- 更新方式与平台有关，也可以从发布页下载新版安装包。详见 [发布说明](docs/RELEASE_NOTES.md)。

## 三步上手

1. **连接模型**：打开侧栏 **模型**，登录支持的账号，或填写 API 地址、密钥和模型。按服务要求准备账号权益或额度。
2. **开始一个具体任务**：新建会话，需要编码时选择项目目录；描述目标、必须保留的内容和验证方式，选择合适的权限模式。
3. **按需连接模块**：在 **插件** 中启用工具，在 **智库** 中整理资料，在 **创作** 中打开画布或白板。需要远程入口或自动任务时，再配置 **渠道** 和 **定时任务**。

界面支持简体中文与 English，可在 **设置 → 外观与字体 → 界面语言** 中切换。完整流程见 [使用指南](docs/USAGE.md)。

## 本地数据与使用边界

- **本地优先不等于离线运行**：会话、资料和应用配置保存在本机。使用云端模型或插件时，完成任务所需的内容会发送给相应服务；本地模型也需要另行配置。
- **备份有明确范围**：支持导出和恢复加密备份，覆盖应用管理的数据、画布及关联资源；不包含登录凭据。外部项目目录应单独备份。详见 [本地文件与数据](docs/LOCAL_FILES.md)。
- **资料导入有格式边界**：当前知识提取以文本为主，没有内置 PDF / Office 解析、OCR 或音视频转写；媒体预览不代表已经完成内容提取。
- **后台任务需要留意额度**：每日记忆整理默认启用，可在 **定时任务** 中暂停或配置；执行时可能消耗所选模型的额度。渠道、定时任务与后台整理需要客户端运行、设备唤醒及所需网络连接。
- **权限会影响真实操作**：完全访问可自动批准已启用工具的操作，终端命令以当前系统用户运行；系统授权与插件配置仍然有效。应用本身不附带模型服务额度。

项目仍在持续开发，已实现范围与验证情况可查看 [实施状态](docs/IMPLEMENTATION_STATUS.md) 和 [验证记录](docs/VALIDATION.md)。

## 从源码运行

需要 Node.js **22.19+**、npm 和 Git：

```bash
git clone https://github.com/OrenZhang/tongzhou.git
cd tongzhou
npm ci
npm run dev
```

Linux 构建原生电脑操作组件还需要 C/C++ 工具链与 X11 / XTest 开发库；Debian / Ubuntu 对应 `libx11-dev`、`libxtst-dev`。更多环境要求见 [贡献指南](CONTRIBUTING.md)。

常用检查与构建命令：

```bash
npm run typecheck
npm test
npm run test:work-capabilities
npm run build
npm run test:desktop
npm run check:i18n
```

`test:work-capabilities` 验证编码、失败后修正、内容入库和任务记忆的完整调用链；使用本地合成模型响应，不调用付费模型。桌面验收需要先构建，并在有图形界面的环境运行。真实服务验证需另行配置账号，不能用本地测试结果代替模型效果评估。
