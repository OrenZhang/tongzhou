# 白板设计

目标是用户能继续编辑、拖动和撤销的白板。用当前会话的 whiteboard 工具完成图形操作，不把说明、Mermaid 文本或一张位图当作可编辑图形交付。

## 入口和资料

- `canvas_list` 确认当前目标；`whiteboard_read` 读取最新版本、图形、选区和 `connections`。已有白板直接修改；只有用户要求新建才 `whiteboard_create`。
- 首次绘图或修复绑定，读 [操作与绑定](references/operations.md)。分支、汇合、回路或较大图，读 [布局与验收](references/layout-and-checks.md)。人物关系图使用人物卡和关系标签；需要生成角色外观图片时切换 `canvas-workflow` 的人物参考，不以几何人形代替媒体生成。
- 官方资料与本产品实际开放范围见 [来源与能力边界](references/sources.md)。官方 API 示例不等于可直接传给 CoSail 工具；参数以当前工具 schema 为准。

## 工作循环

1. 从用户意图和现有图形整理节点与关系。简单图直接做；复杂图先定主干、分支、汇合和回路，再分批提交，每批保留可检查的局部结果。
2. `whiteboard_apply {canvasId,version,ops}`；同一批先创建图形再 `connect`，同批内可以引用刚创建的 ID。每批最多 200 个操作，通常几到几十个足够。不得把版本号猜成“上次加一”；冲突或下一轮需求先读当前状态。
3. 流程关系优先 `connect {id,from,to,text?}`，创建真实端点绑定。已有自由箭头用同 ID 的 `connect` 修复，保留样式、折点和文字；无需删除用户连线。`add arrow` 仅指定坐标得到自由线段，不能用来伪装绑定。
4. 持续修改优先 `update` 原 ID。保留用户未要求的图形、布局、样式、资源、文字和关系。读取失败或目标消失时停止该批改动，重新查明目标，不能清空重建。
5. 再读 `whiteboard_read`，核对 `connections` 每条流程边的 from/to 和 bound，检查新增、修复和删除涉及的元素。成功只说明已核验的结果；若未实测拖动，不声称已验证拖动行为。

## 失败判断

- “不接受字段”表示本次参数不合法，不代表整个能力不存在。优先改用语义操作 `connect`；当前 add/update 也开放 `startBinding/endBinding`，null 表示解绑。
- 历史助手曾把自由箭头误判为“白板不支持绑定”。即使记忆中出现该说法，也应重新读当前工具与连接状态，不让用户替工具手动连线。
- 非法 ID、已删除目标、重复 ID、非图形目标：先读取再修正，不盲重试。结构校验失败的整批未执行；成功后不能重发相同 add 操作。
- 白板不调用 `canvas_execute`；绘图并不执行自动化流程。原生多人在线协作服务、任意网页脚本执行、自动图像生成不是白板工具的能力。
