# 人物与媒体工具应用

## 先锁定人物资料

已有小说/角色文档时从内容库或原文读取，不重编已确认的姓名、年龄、外形、衣着和世界观。多人物长文用 content.split 提取人物；简单一句描述可以直接填入 image.text，不强制多建节点。仅存在文字设定时不要声称已有参考图。

为每个角色维护稳定的角色标识、来源版本和采用图片资源 ID；区分设定稿、候选图、确认稿和生产镜头。图像理解工具若存在，可检查参考图的可见外形；图像理解不等于生图工具。若没有可检查图片的工具，明确“待视觉核对”，不要从生成提示词反推画面已经符合。

## 三视图 / 六格设定图

“三视图”通常是正面、侧面、背面。用户同时要头部和全身时，做两行三列：第一行头部正/侧/背，第二行全身正/侧/背。侧面方向保持一致；不要擅自替换成 3/4 角度。只有用户需要时再增加表情、动作、道具或服装变化。

提示词包含：同一人物、固定发型/发色/瞳色/衣服/配饰、统一比例和光照、正交或低透视、自然中立姿势、完整头部和足部、不裁切、简洁背景。允许整张参考板，但独立生产镜头不应直接把六格拼图当成单帧主画面。后续需要单一视角时，明确选择/生成单视图或由真实可用裁切工具处理，不能编造裁切产物。

参考图优先于重新描述：读取真实资源并设置 media.mode=reference、media.referenceImages，或通过 image.reference 输入连接；只写“参考前图”但未传资源不会构成图像参考。参考数量、尺寸、模型枚举从当前工具 schema 读取。参考提高一致性但不保证完全锁定身份，结果仍需核验。

## 图像工具与模式

先 canvas_list.mediaTools 选择符合 image 的 pluginId/tool，再按 schema 配置 media。不要硬编码 MiniMax 某一代模型、比例、分辨率或数量；公开 API、套餐 API、官方 MCP 的参数并不完全相同。CoSail 会将标准 media 字段映射为工具实际参数，使用者不应同时塞入相互冲突的本地路径/URL 参数。

已有参考资源连接图：

1. 设定文字 `result → image.prompt`。
2. 原件资源 `result → image.reference`（检查输出图像类型）；生成型上游要用 dependency。
3. 生图成功后读取 runs 中 output.resources 和 generation 项，引用实际 artifact/content ID。
4. 为保留用户选中的候选图，后续节点引用已选资源；不要用“最新第一个结果”覆盖用户采用稿。

## 图片接视频、首尾帧、声音

- 图生视频：已采用单帧图 `result → video.firstFrame`，media.mode=first-frame。提示词增加动作、镜头运动、环境变化和节奏，保留人物固定特征。
- 首尾帧：两个真实图片分别连 firstFrame、lastFrame，media.mode=frames；先确认实际生成工具支持尾帧。有尾帧无首帧是无效配置。不能把普通参考图误写成尾帧。
- 多参考主体视频只有当前工具支持才配置；不要因为官网支持就假定当前套餐/MCP 暴露。
- 语音/音乐任务只使用已启用 audio 工具，并核对声音 ID、文本和时长等真实字段。角色配音应保持已确认声音，未经用户要求不克隆声音或主动外发音频。视频、配音与剪辑是不同步骤；没有合成工具不能声称已完成成片。

## 人物成品验收

核对六个视角数量、正侧背方向、头身比例、发型/服饰/配饰一致性、手足完整性、布局间距、文字标签及背景。按实际可见画面说明缺陷，保留可用结果，仅重做失败或用户指定项。最终分清“配置完成 / 正在生成 / 已保存可预览 / 需视觉核对”。资源无法下载时保留远程结果并重试保存，不能再付费生成同一张图来掩盖保存问题。
