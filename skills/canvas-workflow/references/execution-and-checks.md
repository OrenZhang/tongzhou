# 运行、恢复与验收

`canvas_execute` 只启动运行，返回 runId。用 canvas_read 查询对应 runs，读节点 output 和 generation 的状态。已经完成的工作不要再无条件执行。参数校验失败未执行；执行失败可能已经留下部分产物，两者处理不同。

## 恢复决策

| 实际状态               | 后续操作                                                   |
| ---------------------- | ---------------------------------------------------------- |
| 没有生成工具           | 保留节点配置，说明缺少具体能力，等待用户配置               |
| 参数非法               | 查最新定义，修正后再调用；不重复添加成功节点               |
| 仍在异步生成           | 保留任务 ID，按实际工具查询；不另起同一请求                |
| 生成成功、下载失败     | `regenerate.action=save` 且指定 sourceRunId/nodeId/indices |
| 工具支持恢复的中断任务 | `regenerate.action=resume`；核对已有远程任务 ID            |
| 失败项需要重生成       | `regenerate.action=generate`，仅指向失败或用户指定项       |
| 用户取消               | 保留已完成结果，不能自行继续生成                           |

再运行前读最新 version。reuse=true 可复用未改变的输入结果，但不是每次媒体调用的通用去重保证；检查运行记录后再决定。参考边不自动运行上游，dependency 才提供执行顺序；检查是否因为只画了引用线而没有可用产物。

## 按任务规模验证

- 简单文字→模板→保存：执行结果包含正确文本，入库资源可读，未启动媒体服务。
- 人物设定→图片：确认 text 入 prompt，参考图入 reference，工具/model/模式有效，结果资源能预览。
- 小说拆分→人物/场景/道具分支→汇合：动态端口名称正确，不把整段混合输出交给每条分支；检查所有执行依赖和保存结果。
- 人物图→视频首尾帧：两张原件确实分别传入对应端口，身份和方向保持；实际工具不支持的模式应提前报错。
- 定时→处理→通知：核对发布状态、触发条件、时区、真实目标与用户授权；测试模式不向真实收件人发消息。
- 持续修改：改一个角色提示词后，其他节点/资源/位置保持；版本冲突重新读，不清空整个画布。
- 错误恢复：生成与下载分开，失败项恢复不重复已成功项；取消后结果仍保留。

开发测试使用隔离数据和模拟生成服务覆盖入参/输出/状态，不消耗真实媒体额度或通知第三方。需实测在线模型时报告使用的模型与真实调用范围；模拟模型通过不能写成真实供应商生成质量通过。
