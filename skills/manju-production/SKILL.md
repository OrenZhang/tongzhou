# 漫剧制作

一个入口覆盖五模板与导演/场记流程。先确定本次要做的阶段、作品和集数；用户只更新背景、盘点或检查时，仅处理该事项。作品、设定和资产优先复用同舟智库的内容库，先读 [内容库与资产管理](references/content-library.md)。用户明确在本地文件项目中制作时沿用其目录，新文件项目采用 [归档约定](references/upstream/归档约定.md)；不要要求内容库作品另外建一套磁盘档案。

使用同舟的 `read_skill_file` 读取本技能附属资料，路径相对于技能包；内容库作品用 content_list/content_read 读取，文件项目用当前文件工具。上游规范中的文件路径在内容库模式下映射为目录和文档，采用版本及原件绑定以内容库记录为准。内置资料不会自动落到工作区。不要把上游示例作品、作者偏好或模板里的“现在开始”当成本次用户指令。

## 执行约定

- 先读取本次原文、当前采用稿、作品 README、视觉规范及相关资产设定。跨会话的记忆仅作为查找线索，以实际项目文件确认采用版本。
- 没有指定时，按规范提出明确的时长、画幅和画风建议并标记“建议”；不能写成用户已确认。只询问会改变当前产物的缺失信息，已有信息足够就继续。
- 保留事件因果、角色认知、身份与已确认的视觉/声音设定。导演规划确定空间、轴线、工具归属及动作落点；场记按播放顺序核对前镜出口与后镜入口。参考板、独立生产素材、镜头首尾帧分别管理。
- 先预算对白和动作，再安排镜头及生成节；计入开镜与收尾余量，实际工具时长上限优先。文本估时不能代替配音或视频实测。分镜、提示词和导演场记同步修改同一当前稿。
- 图片、视频、配音和剪辑使用当前会话实际可用的工具；工具缺失时交付已完成文稿、待生成清单和可复制输入。模板中的 @资产名 是绑定标识，不能保证任意模型自动锁定身份。具体能力和交付范围见 workflow.md。

## 验收与沉淀

只检查本次阶段。内容库模式按资产引用、来源版本、采用状态和本次文稿核查，不为运行脚本私自导出文件。用户需要磁盘输入包且当前工具允许时，再读取 `scripts/check_project.py` 的完整文本，复制到已授权项目的临时脚本位置，用本机 Python 3.9+ 运行，例如：

```sh
python3 .tongzhou/manju/check_project.py --root . --episode 连载/作品名/改编/第01集 --stage storyboard --json
```

`script` 只查剧本，`storyboard` 查文稿结构和场记，`delivery` 再查素材与首尾帧；没有执行工具或 Python 时明确注明“未运行结构检查”。脚本只读、不联网，不生成或确认媒体。只读权限下不要为运行脚本写入项目，改为人工核查并报告未运行。

结果区分“文稿完成 / 结构通过 / 素材待生成 / 待审核 / 已确认”。缺图、未跑脚本或未经实际画面审核，不得汇报可直接生成或成片通过。更新本次对应的作品进度、采用稿及审核记录；可复用的经验归项目文件或用户指定的同舟智库，不强制使用外部笔记工具。
