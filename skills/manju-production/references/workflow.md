# 同舟制作与验收

## 输入与阶段边界

在内容库执行时，先按 [内容库与资产管理](content-library.md) 定位作品和已采用资产，文稿与设定直接保存到当前库。下文的目录/文件及 Python 检查针对用户要求的文件项目或实际导出包，不要求内容库会话另建磁盘副本。

确认作品、原文范围、集号、目标阶段和本次修改范围；已有剧本、视觉、资产和声音设定先读后用。仅盘点或审计时读取现状并交付问题清单，不顺手生成下一阶段。用户明确要求全流程时，按依赖推进能完成的环节，真实缺失作为待办，不用虚构素材补齐。

五模板分别处理改编、分镜/视频、人物、道具、场景；导演/场记负责空间和动作连续性。不是五个互相独立的 Agent，也不要求额外的多 Agent 编排。会话当前模型和权限继续生效。

## 工具与交付

| 环节 | 可用工具时 | 工具缺失时 |
| --- | --- | --- |
| 文稿/小说 | 读取来源、写入指定稿件、核对因果和认知边界 | 文件写入不可用时在回复交付稿件，注明未落盘 |
| 人物/道具/场景图 | 使用已启用的图像工具并提供真实参考；独立生产图与设定板分开 | 输出提示词、尺寸、参考绑定和审核清单，标记未生成 |
| 首尾帧/视频 | 核对实际模型时长、画幅与参考图能力后提交；保存真实返回文件与生成记录 | 交付逐节输入包计划，首尾帧缺失保持待补齐 |
| 配音/声音 | 为稳定角色绑定实际声音配置，保存音频并测量时长；修订分镜预算 | 交付台词、音色/情绪说明和估时表，标记估算 |
| 剪辑/导出 | 有 FFmpeg 或当前可用剪辑工具时核对输入，依分镜顺序组装，检查输出文件 | 交付播放顺序、转场/声音桥及字幕方案，不称成片已完成 |

不假定同舟已有某个视频、配音或图像服务，不为凑流程安装依赖或更改账号。工具返回的路径先核实文件实际存在，再登记为已生成；用户确认采用前仍是候选。实际审核图像时读取画面，审核视频时覆盖开头、动作关键点、句尾和末帧；只有文本时仅做文稿审查。

## 分镜与场记

采用 `制作规范/02_分镜与视频提示词.md` 的格式，使结构检查能核对 B/S 关联。每个 B 节在标题中记录正数时长，每个 S 镜头只在分镜表里出现一次，生成提示词按相同顺序和镜头覆盖交付。新项目还按导演/场记规范写 JSON：

- 顶层：episode、status、block_order、shots、device_space_limits、changes。
- 每镜：play_order、block、shot、time、scenes、assets、start、end、space_lock、tool_state、open_window、voice_window、close_window。
- `time` 是本 B 节内的开始/结束秒数；`shots` 是播放顺序，不把镜头号重新排序；镜头时间连续，不重叠，末镜终点与 B 节时长一致。
- 固定设备限制对应真实空间，不把画外音设备加入入镜资产来冒充空间连续。逐镜记录每只手、工具接触和出口状态，不能只写“保持一致”。

在导演/场记原规范中查看字段与提示词格式。它们是工作记录，不是让模型展示内部推理；交付明确的制作事实、问题和修订结果即可。

## 结构检查

从技能读取脚本全文并复制到项目临时位置后运行，不把含行号的片段直接保存为 Python 文件：

```sh
python3 .tongzhou/manju/check_project.py --root . --episode 连载/作品名/改编/第01集 --stage script --json
python3 .tongzhou/manju/check_project.py --root . --episode 连载/作品名/改编/第01集 --stage storyboard --json
python3 .tongzhou/manju/check_project.py --root . --episode 连载/作品名/改编/第01集 --stage delivery --max-block-seconds 15 --json
```

入口可从任意工作目录调用，`--root` 指向用户项目，`--episode` 相对该根目录。脚本只使用标准库、不联网、不写业务文件，不要求项目复制本技能的模板或上游 AGENTS.md。上限取实际服务支持值，15秒仅是上游默认兼容上限；目标通常控制在10秒以内，超时先拆节。

| stage | 机器检查范围 | 不代表 |
| --- | --- | --- |
| script | 剧本存在且非空 | 改编忠实、剧情合理、已审核 |
| storyboard | 剧本、分镜、提示词、资产登记、B/S顺序与时长、逐镜场记/时间窗 | 已有图片、真实配音时长、画面连续 |
| delivery | 上述结构 + 整集提示词同步、同名主PNG、首尾帧、素材清单、实际文件非空 | 素材质量通过、用户确认、成片可发布 |

不指定 episode 时检查项目内连载索引与生成记录的相对文件依赖；没有制作档案时报告缺失，不把空项目检查为完成。JSON 输出包含实际检查阶段、统计、错误和 passed 结果；退出码0只表示该范围结构通过，1表示待修正。格式错误和缺失字段应作为问题修复，不能以删除导演场记或资产标识来绕过检查。

## 修订与沉淀

记录具体镜头、失败约束、实际修订和受影响的资产/提示词文件；只修受影响的内容，不另开一套“最终版”。对白实录超预算时修订分镜与场记，再更新输入包；参考图不一致时标记具体角色/机位并等待重新生成或确认，不能只加强“保持一致”的负向提示词。

收尾报告本次阶段、产物路径、实际运行的检查、未生成/待审核项和下一步。把已核实且可复用的设定与经验写回项目或用户指定的同舟智库。内置技能保持可升级；用户明确要求改变工作方法时，可通过同舟的技能创建能力建立个人版本，不在一次制作中悄悄改写全局规则。
