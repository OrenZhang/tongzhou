# 内容库与资产管理

同舟智库的内容库是作品与可复用资产的持久化入口。沿用现有文档、目录、版本和来源关联，不建立另一套资产数据库，也不从客户端存储目录直接改文件。

## 查找与复用

1. 内容文档侧边对话沿用当前 libraryId 和文档。先 content_list 获取真实目录、文档 ID 和摘要，再 content_read 分段读完本次原文、作品索引、视觉规范及相关资产记录；沿 nextOffset 继续读取。
2. 普通会话先定位用户指定的作品/内容库。content_list 返回可用库与当前库文档，可用 libraryId/query 查相关作品；保留其访问范围，库中无结果不代表所有项目都没有资产。存在多个同名作品且上下文无法确定时再询问。
3. 修改前读取当前 version。用 content_write 或 content_patch 更新同一文档，冲突后重新读回并保留用户修改；导入原件保留不变，新建设定/改编稿通过 sourceIds 关联原件。新建省略 id/version。
4. 只按当前任务创建必要目录（content_folder）与文档。保留用户现有分类，不预建空资产或把技能模板全部入库。产出保存后按实际返回 ID 用 content_read 核验。

## 作品和公共资产

没有已有分类时可在一个作品目录下组织「作品索引、原文、视觉规范、公共资产/人物、道具、场景、单集制作」。原规范中的 README、设定.md、资产清单和分镜等各对应一篇内容文档；标题写明作品与对象，目录 ID 使用真实查询结果。

| 记录 | 内容与关联 |
| --- | --- |
| 作品索引 | 原文范围、章/集对应、当前阶段、采用稿和资产记录的文档链接 |
| 人物 | 固定身份与 @名、外观、服装、音色；换装/伤势属于同一人物的状态 |
| 道具 | 固定身份与 @名、结构/尺度/用途、持有者、开合与接触状态 |
| 场景 | 固定身份与 @名、母场景布局、入口/方向/设备、不同机位 |
| 单集资产清单 | 每个 @名引用的设定文档 ID/版本、采用素材原件 ID、具体状态与用途 |
| 分镜/场记/提示词 | B/S编号、时间窗、逐镜状态，关联实际采用的资产及原文版本 |

资产记录本身使用内容文档 ID 作为身份，@名用于制作绑定。正文链接使用 `[[真实文档ID|显示名]]`，避免同名链接歧义；sourceIds 保存本次实际采用的来源版本并形成反向引用。可用 contentType 标识 manju/character、manju/prop、manju/scene 或 manju/manifest，但不依赖不存在的专用字段或枚举。

一份设定记录维护当前采用状态及必要候选，媒体原件分别保存。状态/候选/已采用/弃用写在正文中；同舟 ready/draft 是知识状态，不能当作用户已确认采用。引用来源版本变化时先比较变更，列明受影响的集数/镜头，不直接让新候选替换已采用素材。

资产记录可使用以下精简结构，仅填写实际已有的内容：

```markdown
# 作品名 · 人物 · 林舟
固定名：@林舟
已确认设定：……
当前采用：状态「冬装」，设定版本 v2；确认依据：……

| 状态/用途 | 原件链接 | 记录版本 | 采用状态 | 约束 |
| 冬装/主素材 | [[实际原件ID|林舟冬装.png]] | v1 | 待审核 | 单人独立素材 |
| 冬装/参考板 | [[另一实际原件ID|人物参考板.png]] | v1 | 候选 | 不直接充当镜头首帧 |

使用位置：第01集 EP01_B001；具体镜头状态见单集清单。
```

示例中的 ID 必须替换为真实查询或保存结果；没有媒体原件时明确「待生成」，不伪造链接。

## 媒体原件与生成作品

- content_read 默认读记录；需要核对图片时加 `includeImage: true`，只对实际返回图像做视觉判断。目前支持 3 MB 内的 PNG/JPEG/WebP。其他媒体、过大图片或未返回图像时，不能声称已看过/听过；使用实际可用的媒体工具处理，或标记待审。
- 普通会话可通过 client_catalog 查询 contentImport，把用户指定本地文件导入指定 libraryId/folderId；其结果才是内容库原件。每个文件当前最多25 MB，较大视频保留用户授权的外部/项目文件位置与记录，不能称已入库。
- 新生成作品先按实际工具结果登记，用户要求归入作品资产时通过 artifactToKnowledge 保存到目标库/目录，返回真实文档 ID。它保存独立原件；远程链接作品需先实际取得文件，否则只记录链接。
- 将设定文档/单集清单通过 sourceIds 与导入原件关联。媒体文件名可含状态版本，@固定名保持不变。参考板、独立主素材、状态图、首尾帧、声音/视频分开记录用途；不能把参考板误标为主素材或把首尾帧当作新人物。
- 图片生成服务支持参考图时，必须传递它实际接受的文件、图像或素材 ID。内容库 ID 和 @名是管理标识，不是可直接发送给所有生成服务的引用参数。

## 输入包与验收

用户需要文件输入包，且当前会话有导出/文件工具时，通过 client_catalog 查询 contentExport：位置参数为 `[文档ID, 目标绝对路径, 覆盖所需SHA256, 是否导出原件]`。导出媒体原件使用第四项 true；普通正文导出保持默认。目标不存在时无需 SHA256（可传 null 占位），已有文件须先核对哈希。主素材导出为 `素材/<固定名>.png` 前确认它实际是 PNG，不能仅改扩展名。

内容文档侧边对话没有本地命令和客户端管理工具时，直接在当前库交付设定、清单、分镜和提示词；不能尝试读取内部 blob、绕过当前库范围或声称已创建磁盘输入包。需要导入/下载可使用内容库界面；实际文件项目阶段再运行结构检查。

完成前核对真实文档/原件存在、引用版本、状态及资产用途，记录本次检查范围和缺失。内容库核对不等于 Python 磁盘检查通过，也不等于媒体质量审核通过；仅在用户确认后更新采用状态和受影响清单。
